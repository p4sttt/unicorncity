# Московская проблема: положительно взвешенный K4

Получено самодостаточное доказательство существования остовного дерева с исходными весами и $L_G\preceq(2+4\cos(\pi/9))L_T$. Коэффициент примерно $5.75877$ лучше Московского порога $6$ для этого графового класса. Общая гипотеза для произвольных вещественных фреймов не решена; научный приоритет результата не установлен.

- [Независимый неформальный аудит](independent_audit.md): проверка отдельным AI-агентом. Ещё один агент независимо проверил компактификацию и три тождества. Это не внешнее рецензирование и не формальная верификация.

## Протокол численного поиска

Порядок рёбер в скриптах с нумерацией вершин от нуля: `01, 02, 03, 12, 13, 23`. Для каждого из 16 деревьев вычисляется наибольшее обобщённое собственное значение пары $(L_G,L_T)$ и выбирается наименьшее среди деревьев. Положив $C=B_T^{-1}B$, скрипт диагонализует симметричную матрицу $\operatorname{diag}(w_T)^{-1/2}C\operatorname{diag}(w)C^T\operatorname{diag}(w_T)^{-1/2}$.

Seed `17029`; по 3000 случайных стартов для трёх диапазонов логарифмов весов с границами 3, 8 и 14, затем локальное уточнение восьми лучших стартов в каждом диапазоне методом Nelder–Mead. Общий масштаб удалён фиксацией последнего веса в 1; логарифмы при локальном поиске ограничены по модулю 30. В дополнительном скрипте seed `913` и малый поиск для пяти рёбер. Это короткий исследовательский поиск на NumPy, без доказанной глобальности и без интервального контроля ошибок.

Лучший найденный общий положительный пример имел веса приблизительно $(1.00012724,0.56163490,0.99999396,1.00011149,0.56152643,1)$ и коэффициент $5.56122596$. Он мотивировал точный анализ семейства $(1,t,1,1,t,1)$, в котором максимум равен $(7+\sqrt{17})/2$. Теорема для произвольных положительных весов опирается на аналитический аргумент, а не на отсутствие контрпримеров в этом поиске.

## Воспроизведение

Из корня репозитория, используя Python 3:

```bash
python3 docs/research/moscow_k4_2026_10_04/verify_sharp_identities.py
python3 docs/research/moscow_k4_2026_10_04/verify_analytic.py
python3 docs/research/moscow_k4_2026_10_04/exact_family.py
```

Эти три проверки используют только стандартную библиотеку. Повторение численного поиска требует NumPy и перезаписывает соответствующие JSON, включая время запуска:

```bash
python3 docs/research/moscow_k4_2026_10_04/explore.py
python3 docs/research/moscow_k4_2026_10_04/followup.py
```

Исходные численные измерения сохранены; после переноса скриптов в репозиторий повторены точные проверки. Никакой результат не требует обучения модели, GPU или установки SciPy/SymPy.
