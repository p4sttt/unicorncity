# Вероятностная декомпозиция области

## Definition

**Probabilistic domain decomposition (PDD)** — гибридная схема, в которой значения решения
в **немногих** точках на внутренних интерфейсах вычисляются методом Монте-Карло по
вероятностному представлению решения, затем интерполируются вдоль интерфейса (обычно
по Чебышёву), и полученные следы используются как граничные условия, **полностью
развязывающие** подобласти. Дальше каждая подзадача решается независимо любым классическим
методом.

## Intuition

Итерации в классическом DD нужны ровно потому, что решение УрЧП глобально: значение внутри
области нельзя получить, не решив всю задачу. Формула Фейнмана–Каца ломает именно это
предположение — она даёт $u(x)$ в **отдельной точке** как математическое ожидание вдоль
траекторий диффузии:

$$
u(x) = \mathbb{E}^L_x \left[
g(\beta(\tau_{\partial\Omega})) e^{-\int_0^{\tau} c(\beta(s))\,ds}
- \int_0^{\tau_{\partial\Omega}} f(\beta(t)) e^{-\int_0^t c\,ds}\, dt
\right]
$$

где $\beta(t)$ решает СДУ $d\beta = b(x)\,dt + \sigma(x)\,dW(t)$, а
$\tau_{\partial\Omega}$ — время первого выхода на границу. Если известны следы на
интерфейсах, коммуникация между процессорами исчезает вообще.

Отсюда два свойства, которых детерминированный DD не даёт бесплатно:

- **Масштабируемость.** Нет обмена данными через интерфейсы, нет итераций, нет
  ill-conditioned интерфейсного оператора и нет нужды в предобусловливателе.
- **Отказоустойчивость.** Если из $N$ процессоров отказали $n$, результат остаётся
  осмысленным — ошибка деградирует как $O((N-n)^{-1/2})$, то есть при потере 1%
  процессоров ошибка растёт примерно в 1.005 раза.

## Formal description

Алгоритм в трёх строках:

1. Вычислить немногие интерфейсные значения методом Монте-Карло по формуле выше.
2. Интерполировать по этим узлам, получив граничные данные для подобластей.
3. Решить задачу в каждой подобласти стандартным методом (конечные разности / FEM).

**Источники ошибки** (все, кроме первого, часто игнорируются в литературе):

1. Статистическая ошибка конечной выборки: $O(N^{-1/2})$.
2. Ошибка усечения при численном решении СДУ.
3. Неопределённость оценки **времени и точки первого выхода**. Эффективный приём —
   экспоненциальный шаг по времени (Jansons–Lythe), допускающий явную аналитическую форму
   вероятности попадания на границу.
4. Ошибка квадратуры в самой формуле (отсутствует, если $c \equiv 0$ и $f \equiv 0$).

**quasi-PDD.** Замена псевдослучайных чисел последовательностями квази-случайных
(Ниедеррайтер) меняет порядок ошибки с $O(N^{-1/2})$ на $O(N^{-1}\log^{d^*-1} N)$.
Оговорка, которую авторы называют честно: квази-случайные последовательности требуют
переупорядочивания на каждом шаге, чтобы разбить внутренние корреляции, а это затрудняет
параллелизацию — то есть выигрыш в точности может съесть выигрыш в масштабируемости.

**Почему грубая точность в узлах не убивает метод.** Пивотальные значения из Монте-Карло
неточны, и интерполяция добавляет свою ошибку, но по принципу максимума ошибка внутри
подобласти мажорируется граничной и быстро убывает вглубь.

## Эмпирика

Сравнение с детерминированным DD (пакет pARMS: overlapping Schwarz + FGMRES с ILUT), MPI,
MareNostrum, задача Лапласа на $(0,p)\times(0,1)$ с фиксированной нагрузкой на процессор
([[acebron_spigler_scalable_parallel_elliptic]]):

| процессоров | DD, с | PDD, с |
|---|---|---|
| 4 | 110.5 | 84.1 |
| 16 | 163.8 | 90.8 |
| 64 | 335.2 | 88.9 |
| 128 | 14184.4 | 102.2 |
| 256–1024 | не доступно | 132–148 |

Время PDD практически не растёт с числом процессоров; время детерминированного DD
взрывается из-за межпроцессорного обмена, и после 128 процессоров сравнение прекращается.

Более ранний OpenMP-эксперимент ([[acebron_spigler_probabilistic_dd]]) на 16-процессорной
IBM Power 3 против параллельных конечных разностей при сопоставимой максимальной ошибке
$10^{-3}$: 16 процессоров — 2638.9 с (PFD) против 175.2 с (PDD), из которых на Монте-Карло
уходит всего 3.4 с, остальное — локальные решатели.

## Связь с классической теорией

Вероятностная интерпретация Шварца — не только вычислительный приём, но и **способ
доказательства**. Лионс в [[lions_schwarz_alternating_ii]] выражает итераты Шварца через
последовательные времена выхода:

$$
\tau_x^{2n+1} = \inf\{t \ge \tau_x^{2n} : x + B_t \notin \Omega_1\}, \qquad
\tau_x^{2n} = \inf\{t \ge \tau_x^{2n-1} : x + B_t \notin \Omega_2\}
$$

$$
u^n(x) = \mathbb{E}\left[\int_0^{\tau_x^n} f(x + B_t)\, dt\right] + u^0(x + B_{\tau_x^n})
$$

и получает геометрическую сходимость чисто вероятностно. Этот путь даёт подсказку, **как
оптимизировать разбиение области** для наибыстрейшей сходимости — чего вариационное
доказательство не даёт.

## Open questions

- Область применения ограничена задачами, для которых удаётся точно оценивать время и точку
  первого выхода; для сильно нерегулярных границ это тяжело (для кусочно-линейных —
  приемлемо).
- Точность привязана к $N^{-1/2}$: PDD выигрывает по масштабируемости и отказоустойчивости,
  но не претендует на превосходство по точности над детерминированными кодами.
