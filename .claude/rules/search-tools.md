# Search tooling: qmd

Когда ищешь релевантные страницы в `wiki/` для ответа на вопрос или перед ingest (проверка на дубликаты/пересечения) — используй `qmd`, а не читай все страницы подряд. Сначала смотри карту через поиск, и только потом открывай найденные страницы целиком.

## Индексация (один раз на коллекцию, дальше — при добавлении новых страниц)

```bash
# Создать коллекцию из wiki/
qmd collection add ./wiki --name wiki

# Проиндексировать для полнотекстового поиска (обязательно после каждого ingest)
qmd update

# Построить embeddings для семантического поиска (не обязательно на каждый ingest,
# можно раз в несколько сессий или когда нужен --query с семантикой)
qmd embed
```

## Поиск — три режима, используй нужный под задачу

```bash
# Быстрый keyword-поиск (BM25) — когда знаешь точный термин/название
qmd search "policy gradient"

# Семантический поиск — когда формулировка вопроса не совпадает с текстом страниц
qmd vsearch "как агент выбирает действие"

# Гибридный поиск с LLM-реранкингом — лучшее качество, используй по умолчанию для query-операций
qmd query "connection between KL divergence and trust region methods"
```

## Полезные флаги

```bash
qmd query -n 10 --min-score 0.3 "тема"   # больше результатов, отсечь низкий score
qmd query --md --full "тема"              # markdown-вывод с полным текстом — удобно вставлять в контекст
qmd query --files "тема"                  # только docid,score,filepath — для быстрой навигации без содержимого
qmd status                                # проверить состояние индекса перед поиском, если результаты выглядят подозрительно пустыми
```

## Получение конкретной страницы после того как нашёл нужный docid/путь

```bash
qmd get wiki/concepts/policy-gradient.md          # весь файл
qmd get wiki/concepts/policy-gradient.md:50 -l 100  # с 50 строки, максимум 100 строк
qmd get "#a1b2c3"                                   # по docid из результатов поиска
qmd multi-get "wiki/concepts/*.md" --max-bytes 20480  # несколько файлов сразу, с лимитом размера
```

## Workflow для query-операции (см. CLAUDE.md, раздел Query)

1. `qmd query "<переформулированный вопрос>"` — получить top-кандидатов, а не читать index.md целиком
2. Отобрать 5–10 релевантных страниц по score и заголовкам
3. `qmd get` / `qmd multi-get` только на эти страницы — не открывай всё, что нашлось
4. Синтезировать ответ с ссылками на конкретные страницы вики

## Не делай

- Не грепай/читай файлы в `wiki/` напрямую инструментом Read, если можно сначала сузить через `qmd query` — цель именно в том, чтобы не сканировать всю вики на каждый вопрос.
- Не забывай `qmd update` после ingest — если индекс не обновлён, поиск будет находить старую версию страниц или не находить новые вовсе.
- Если меняешь embedding-модель — обязательно `qmd embed -f` (полный переиндекс), векторы разных моделей несовместимы.
