## TL;DR

Stacked Borrows — операционная семантика памяти Rust, которая «динамически» воспроизводит borrow checker: каждому адресу памяти сопоставляется стек тегированных элементов. Нарушение стекового порядка доступов объявляется UB, что даёт компилятору право переупорядочивать обращения к памяти без глобального анализа. Модель реализована в интерпретаторе Miri и формально верифицирована в Coq.

## Core contribution

- Первая формальная операционная семантика, позволяющая обосновать алиасинг-оптимизации Rust *интрапроцедурно*, даже когда вызываются неизвестные функции.
- Баланс между «слишком много UB» (сломает реальный unsafe-код) и «слишком мало UB» (не позволит оптимизациям).
- Реализация Stacked Borrows в Miri + прогон тест-сьюта stdlib; механизированные доказательства в Coq.

## Method

### Ключевая идея: borrow stack

Каждая ячейка памяти хранит пару `(значение, стек элементов)`. Элемент стека — одно из:

| Элемент | Смысл |
|---------|-------|
| `Unique(t)` | Тег `t` — уникальный изменяемый указатель; на вершине — активен |
| `SharedRO(t)` | Тег `t` — разделяемая ссылка только для чтения |
| `SharedRW(t)` | Тег `t` — разделяемый указатель с правом записи (raw pointer / UnsafeCell) |

**Теги** — уникальные идентификаторы, присваиваемые при создании ссылки. Raw pointer'ы получают тег `⊥` (untagged) → ещё один вид `SharedRW(⊥)`.

### Правила создания и доступа

- **new-mutable-ref**: создание `&mut T` из `Pointer(ℓ, t)` считается использованием `t` (всплывает по стеку), затем пушится `Unique(t')` с новым тегом.
- **use-2**: запись через `Pointer(ℓ, t)` — элемент с тегом `t` должен быть в стеке; все элементы выше него снимаются (делаются инвалидными).
- **read-1**: чтение — элемент с тегом `t` должен быть в стеке; снимаются все элементы выше, *кроме* `SharedRO`.

### Retag и протекторы

- Компилятор вставляет инструкцию `retag` при каждом «входе» ссылки в область видимости — эффективно это reborrow с новым тегом.
- `retag[fn]` (для аргументов функций) добавляет **протектор**: снятие соответствующего элемента с вершины стека *во время активного вызова* является UB. Это соответствует правилу Rust «ссылка аргумента должна пережить вызов».

### Interior mutability

`UnsafeCell<T>` обрабатывается особо: вместо `SharedRO` туда кладётся `SharedRW` — допускается мутация через разделяемую ссылку.

### Доказанные оптимизации

```
fn example(x: &mut i32) → i32 {
    retag[fn] x;
    *x = 42;
    <unknown_code_not_using_x>();
    *x  // → можно заменить на константу 42
}
```

Ключ — после `retag[fn]` тег `x` гарантированно на вершине; любое обращение к `ℓ` через другой тег снимет его (UB), значит неизвестный код не мог трогать `*x`.

## Key results

- Miri + stdlib test suite: бо́льшая часть тестов прошла без изменений; найдено несколько нарушений, признанных багами Rust и исправленных.
- Coq: механизированные доказательства для переупорядочивания чтений/записей вокруг неизвестного кода (intra-procedural alias analysis).
- Семантика позволяет компилятору добавить атрибут `noalias` к ссылкам на уровне LLVM IR.

## Limitations

- **Стек** не поддерживает two-phase borrows (introduced after SB) — в реализации Miri treated as raw pointers, что порождает контринтуитивное поведение.
- Отклоняет паттерн «создай ссылку на первый элемент массива, затем через raw pointer обратись к другим элементам» — ограничивает диапазон памяти типом ссылки (статические bounds).
- Нельзя переупорядочивать чтения без ограничений: read-read reordering иногда даёт UB из-за поведения `Unique → Disabled` при foreign read.
- Только sequential semantics; concurrency — за рамками.

## My notes

- Retag как «виртуальный reborrow» — элегантный способ перевести статические lifetimes в динамическую проверку без их явного отслеживания.
- Протекторы — прямое операционное отражение правила `outlives` из borrow checker.
- Предвидение авторов: «В future work хотели бы отслеживать дерево указателей вместо стека» — именно это и стало Tree Borrows.
- Центральный трейдофф: стек требует well-nested usage; tree borrows ослабляет это до DAG-иерархии, выигрывая в реальном коде.
